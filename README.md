# وب‌اپ مشتریان مهر

نمونه اجرایی مستقل پنل خرید خودرو با دو بازار:

- طرح‌های فروش
- تأمین خودروهای کارکرده

مسیر نمایشی خودروی کارکرده شامل درخواست تأمین، پیشنهاد نسخه‌دار مدیر تأمین، بیعانه ۲۰۰ میلیون تومانی، کارشناسی مبدا، Certificate Report، تصمیم مشتری، پرداخت مانده و سفر رویدادمحور خودرو تا تحویل است.

رابط داده را فقط از مسیر `/customer-api/v1` می‌خواند. کاتالوگ امکان اتصال سروربه‌سرور به Customer API را دارد؛ هویت، پرونده خرید و پرداخت فعلاً نمایشی‌اند. مرورگر هرگز مستقیم به سامانه داخلی یا دیتابیس وصل نمی‌شود.

## اجرا

```bash
npm install
npm run dev
```

سپس `http://127.0.0.1:3001` را باز کنید.

نماهای پرتال مستقل و قابل لینک‌اند:

- `#/home` خانه و گاراژ شخصی
- `#/buy` بازار خودرو
- `#/buy/saved` علاقه‌مندی‌های همین دستگاه
- `#/requests` پرونده‌های خرید
- `#/requests/{caseId}` لینک مستقیم پرونده متعلق به مشتری
- `#/documents` مدارک من
- `#/notifications` اعلان‌ها
- `#/aftersales` طراحی خدمات پس از فروش، نوبت و دستیار (هنوز متصل نیست)
- `#/account` حساب من

## کنترل کیفیت

```bash
npm run check
node scripts/check-customer-media.mjs
```

## وضعیت اتصال

- UI، فیلتر، جزئیات و ثبت درخواست آزمایشی فعال‌اند.
- یک پرونده نمونه پیشنهاد و یک پرونده فعال در مرحله ترخیص برای مشاهده مسیر گرافیکی هفت‌ایستگاهی، ETA، رویداد جاری و تأییدهای انجام‌شده در بخش «درخواست‌های من» قرار دارد.
- هویت فعلی Principal نمایشی سمت سرور است؛ پیش از اتصال زنده باید به OTP/Session پرتال وصل شود.
- قرارداد داده و معماری اتصال در `docs/` مستند شده‌اند.
- تصاویر نمونه برای خودروهای کارکرده نمایش داده نمی‌شوند. دریافت واقعی عکس نیازمند انتشار رسانه همان listing از Customer API است؛ URL خصوصی منبع به مرورگر منتقل نمی‌شود.
- جست‌وجو فعلاً روی فهرست دریافتی حداکثر ۲۰۰ خودرو انجام می‌شود، نه کل مجموعه ۱۰۰هزارتایی. صفحه‌بندی و جست‌وجوی سمت سامانه لازم است.
- نیازهای موبایل و APIهای مرحله بعد در [طرح تجربه مشتری](docs/MOBILE-CUSTOMER-EXPERIENCE.fa.md) و [قرارداد رسانه خودرو](docs/CUSTOMER-VEHICLE-MEDIA.fa.md) آمده‌اند.
- در این نوبت تغییر سامانه داخلی، GitHub یا انتشار عمومی انجام نشده است.
