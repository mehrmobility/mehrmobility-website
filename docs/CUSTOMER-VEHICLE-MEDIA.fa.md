# عکس واقعی خودروی کارکرده — اتصال موردنیاز سامانه

درخواست کاربر: عکس واقعی خودرو از سامانه مهر نمایش داده شود. تغییرات این نوبت فقط در وب‌اپ انجام شدند؛ موارد سمت سامانه زیر نیازمند اجرا در پروژه سامانه‌اند.

## یافته فعلی

سامانه عکس اول آگهی را در `used_car_market_listing.data_json.imageUrl` نگه می‌دارد. ورودی Dubizzle از `photos` و DubiCars از `imageUrl/imageUrls` می‌آید؛ امروز فقط اولین URL نگهداری می‌شود. فایل `lib/market-media.ts` دامنه‌های منبع را کنترل می‌کند. رابط کارکنان از آن استفاده می‌کند، ولی Customer API و bridge آیوِن تصویر ثابت و گالری خالی می‌دهند. endpoint رسانه مشتری وجود ندارد. تأیید قیمت، تأیید حق انتشار تصویر نیست.

## آنچه در وب‌اپ آماده شد

- تصویر یکسان نمونه از کارت و جزئیات خودروهای کارکرده حذف شد. در نبود عکس پیام صریح نشان داده می‌شود.
- دریافت رسانه فقط از BFF خود وب‌اپ انجام می‌شود؛ مرورگر URL منبع، توکن سامانه یا شناسه داخلی نمی‌بیند.
- شناسه عکس باید در رسانه منتشرشده همان listing باشد؛ تعویض شناسه، URL دلخواه، redirect، محتوای SVG/HTML و فایل بیش از ۵ MiB رد می‌شوند.
- MIME و امضای JPEG/PNG/WebP هر دو کنترل می‌شوند. درخواست بالادستی حداکثر ۱۰ ثانیه مهلت دارد. پاسخ `private,no-store`، `nosniff` و `Cross-Origin-Resource-Policy:same-origin` دارد.
- خطای تصویر به وضعیت «دریافت تصویر ممکن نشد» تبدیل می‌شود؛ تصویر ساختگی جای آن قرار نمی‌گیرد.
- تصاویر خصوصی و thumbnailها مستقیماً با نشست مرورگر دریافت می‌شوند و از بهینه‌ساز/کش مشترک Next عبور نمی‌کنند؛ حذف این قاعده هم احراز هویت و هم ابطال انتشار را مختل می‌کند.
- چند تصویر تأییدشده در گالری قابل انتخاب‌اند. عکس منبع «تصویر آگهی مبدأ» نام دارد، نه عکس کارشناسی مهر.

## قرارداد لازم در فهرست و جزئیات سامانه

نمونه صرفاً ساختار قرارداد است، نه داده یک خودروی واقعی:

```json
{
  "id": "used_public_listing_001",
  "customerMedia": [
    {
      "id": "media_public_image_001",
      "listingId": "used_public_listing_001",
      "kind": "IMAGE",
      "subject": "LISTING_VEHICLE",
      "publicationState": "PUBLISHED",
      "publicationAudience": "CUSTOMER",
      "rightsState": "APPROVED",
      "scanState": "CLEAN",
      "redactionState": "APPROVED"
    }
  ]
}
```

حداکثر ۲۰ عکس؛ نخستین عکس معتبر کاور است و بقیه گالری. BFF هیچ URL رسانه را از این metadata نمی‌پذیرد و مسیر را خودش از شناسه‌های عمومی می‌سازد. فیلدهای `imageUrl` و `gallery` قدیمی برای سازگاری v1 هنوز در ورودی الزامی‌اند؛ برای کارکرده فقط `customerMedia` معتبر می‌تواند عکس قابل نمایش ایجاد کند.

سامانه باید نسبت عکس و همان listing، نسخه منبع، حق بازنشر، scan و حذف اطلاعات قابل شناسایی/یادداشت داخلی را واقعاً بررسی کند. افزودن این markerها با مقدار ثابت بدون اجرای بررسی معتبر نیست. با تغییر URL/نسخه عکس، تأیید رسانه قبلی باطل شود. ابطال انتشار باید در درخواست بعدی رسانه اعمال شود؛ لینک قدیمی مجوز مستقل نیست.

## endpoint خصوصی موردنیاز سامانه

```text
GET /v1/listings/{publicListingId}/media/{publicMediaId}
Authorization: Bearer <credential فقط سمت سرور>
X-Mehr-Customer-Subject: <subject معتبر از BFF>

200 image/jpeg | image/png | image/webp
403/404 برای رسانه نامجاز، حذف‌شده یا نامرتبط
```

احراز سرویس و کنترل نشر دوباره، ثبت Audit خواندن، تبدیل عکس به derivative مشتری با حذف EXIF/GPS و اطلاعات حساس، و محدودیت سایز در مبدأ لازم است. نسخه و object key خصوصی از DTO حذف شوند. دریافت URL خارجی فقط داخل سرویس رسانه و با allowlist، منع مقصد خصوصی/لوپ‌بک، کنترل DNS/redirect و سقف حجم انجام شود؛ مسیر proxy آزاد ساخته نشود.

مسیر آماده وب‌اپ:

```text
GET /customer-api/v1/marketplace/listings/{publicListingId}/media/{publicMediaId}
```

با اضافه‌شدن metadata و endpoint فوق به Customer API سامانه، کارت و گالری بدون دسترسی مستقیم مرورگر به منبع یا دیتابیس، عکس واقعی آگهی را می‌خوانند. فعلاً عکس زنده دریافت نشده است. مهاجرت کامل به gallery نیازمند نگهداری تصاویر بعدی در ورودی سامانه است.

## نتیجه بررسی محلی — ۱۲ سپتامبر ۲۰۲۶

- صفحه اصلی پاسخ ۲۰۰ داد. فهرست کارکرده ۱۳۲ رکورد برگرداند؛ تعداد عکس منتشرشده از مسیر رسانه مشتری صفر بود. این عدد شمار فهرست دریافتی است، نه کل موجودی سامانه.
- مسیر شناسه رسانه ناشناخته پاسخ ۴۰۴ داد.
- تست‌های ایزوله تعلق عکس، مجوزها، ابطال، سقف حجم، MIME/امضا و نسخه خلاصه تأییدشده موفق شدند (`node scripts/check-customer-media.mjs`). این تست‌ها از fixture استفاده می‌کنند، نه عکس زنده.
- `npm run check` شامل typecheck، lint و build موفق شد؛ lint دارای ۱۹ هشدار قدیمی تصاویر بخش عمومی `/mehr` و بدون خطا بود.
- تست دیداری/لمسی مرورگر در این نوبت انجام نشد. سامانه داخلی تغییر نکرد و نسخه‌ای منتشر نشد.
