# معماری استاندارد کنسول مدیریت مهر

کنسول مدیریت مهر باید یک CMS مستقل از سامانه داخلی خودرو باشد؛ نه یک ویرایشگر JSON در مرورگر. مدل پیشنهادی با الگوی CMSهای سازمانی شامل حوزه‌های زیر است:

## Workspaceها

1. **Content Studio**: صفحات، بخش‌ها، مقالات، اطلاعیه‌ها، صفحات خودرو و SEO.
2. **Navigation**: منوهای دسکتاپ/موبایل/فوتر، لینک‌های داخلی و خارجی، ترتیب، پیش‌نویس و انتشار.
3. **Media Library**: تصویر، PDF و ویدیو با مالکیت، حق استفاده، اندازه، نسخه‌های responsive و چرخه تأیید.
4. **Catalog**: مدل خودرو، مشخصات، گالری، کاتالوگ، وضعیت انتشار و تغییرات قابل بازگشت.
5. **SEO & Redirects**: عنوان، description، canonical، Open Graph، schema، sitemap و ریدایرکت‌های میراثی.
6. **Support**: صف درخواست‌های عمومی و دانش‌نامه؛ جدا از پرونده و قرارداد خصوصی مشتری.
7. **Settings**: هویت برند، راه‌های تماس، شعب، شبکه‌های اجتماعی، پیام‌های سراسری و feature flagها.
8. **Access & Audit**: نقش‌ها، سطح دسترسی، نشست‌ها، تاریخچه تغییر، تأیید انتشار و بازگردانی نسخه.

## مدل انتشار

هر رکورد محتوا و منو باید `draft → in_review → approved → published → archived` داشته باشد. فقط رکورد published می‌تواند روی سایت عمومی دیده شود. حذف به‌صورت soft delete انجام می‌شود و هر تغییر شامل editor، timestamp، revision و دلیل تغییر است.

## نقش‌ها

- `SYSTEM_ADMIN`: تنظیمات، نقش‌ها و انتشار نهایی.
- `CONTENT_EDITOR`: ایجاد و ویرایش پیش‌نویس.
- `REVIEWER`: بازبینی و تأیید محتوا.
- `CATALOG_MANAGER`: مدیریت خودرو و رسانه کاتالوگ.
- `SUPPORT_AGENT`: فقط صف پشتیبانی مجاز.
- `SEO_MANAGER`: SEO، sitemap و redirectها.

## مرزهای قطعی

- مرورگر CMS به دیتابیس داخلی، CIF، سود، نرخ ارز، تأمین‌کننده، حمل‌کننده یا VIN پیشنهادی دسترسی ندارد.
- داده خصوصی مشتری فقط از Customer Read Model و با RBAC، کنترل مالکیت، Audit و API سروری خوانده می‌شود.
- انتشار ویدیو/مدارک مشتری نیازمند فضای فایل خصوصی، malware scan، URL کوتاه‌عمر و بررسی مجوز است.

## مسیر مهاجرت

1. انتقال محتوا و منوهای فعلی از فایل‌های ثابت به جدول‌های versioned CMS.
2. اعمال read API منتشرشده روی صفحات عمومی؛ مسیرهای draft فقط برای اپراتور مجاز قابل preview باشند.
3. اضافه کردن Media Library و workflow تأیید.
4. انتقال کامل کاتالوگ به Catalog API؛ حذف مستقیم فایل JSON.
5. اتصال پشتیبانی و سپس Customer Read Model، بدون مخلوط کردن آن با CMS عمومی.
